# Due 项目专属编码规范

本文件独立维护 Due 的项目约定，便于后续追加规则。适用范围与 [Go 编码规范入口](go-style.md)一致，覆盖框架、独立模块、组件、工具、示例、测试和基准测试中的手写 Go 代码。

## 一、规范优先级

Due 以 [Uber Go Style Guide](uber-go/style.md)作为通用编码规范。本文件补充项目约定；与通用规范存在冲突时，优先执行本文件中适用的 Due 规则，其余部分继续遵循 Uber 指南。

其中，`DUE-003` 是对 Uber `Defer to Clean Up` 在高性能场景下的明确覆盖。项目约定不能以遗漏资源清理、破坏错误处理或引入并发错误为代价。

| 编号 | 主题 | 要求 |

## 三、规则详情

### DUE-001

**JSON 编码与解码统一使用 Due JSON 包（强制）。**

在使用 JSON 编码、解码的场景中，必须使用：

```go
import "github.com/dobyte/due/v2/encoding/json"
```

- JSON 编码、解码统一通过该包的 `json.Marshal`、`json.Unmarshal` 或相应的编解码入口完成。
- 调用方不得直接使用标准库 `encoding/json` 或第三方 JSON 编解码器替代 Due 的统一入口。
- 需要当前封装未提供的能力时，应评估扩展统一封装或在其能力范围内实现，不直接绕过本规则。

### DUE-002

**需要使用 errors 包时统一使用 Due errors 包（强制）。**

在需要使用 errors 包的场景中，必须使用：

```go
import "github.com/dobyte/due/v2/errors"
```

- 错误创建、匹配、类型断言和解包等包操作，使用 Due 提供的 `errors.New`、`errors.Is`、`errors.As`、`errors.Unwrap` 等对应 API。
- 调用方不得用标准库 `errors` 或其他错误库替代该统一入口；设置导入别名也不改变这一要求。
- 内建 `error` 类型、原样返回错误和普通错误检查仍按 Go 语义与通用规范执行，不要求为每个错误强制转换为 Due 自定义错误类型。

`DUE-001` 和 `DUE-002` 约束封装包的使用方。统一封装自身需依赖底层实现，不能导入自身；其内部适配依赖不构成其他代码绕过统一入口的理由。

### DUE-003

**高性能场景下，能不用 Go `defer` 就不用。**

- 对已明确属于高性能场景的代码，优先通过显式清理、合理组织退出路径等方式减少可避免的 `defer`，例如消息处理、编解码、网络读写和高频调度等实际热点。
- 显式清理必须覆盖相关退出路径，保持资源释放、解锁、取消和其他清理行为正确；不能仅删除 `defer` 而遗漏原有清理。
- 无法可靠保持清理语义时，保留必要的 `defer`。普通场景继续遵循 Uber 使用 `defer` 清理的通用规则。
- 本条作为 Due 项目约定优先执行，不以 Uber 指南中的“函数执行时间处于纳秒量级”条件作为高性能场景适用本条的前提。具体性能改善仍需实际测量，不能仅凭移除 `defer` 宣称提速。

### DUE-004

**无强制时区要求的场景，只能使用标准库 time 包（强制）。**

```go
import "time"
```

- 没有明确的强制时区要求时，时间获取、时长计算、定时器和常规时间处理统一使用 `time` 包。
- 此类场景不得以 `github.com/dobyte/due/v2/utils/xtime` 或第三方时间包替代 `time`。
- 继续遵循通用规范：时间点使用 `time.Time`，时长使用 `time.Duration`，外部时间表示明确格式或单位。
- 有强制时区要求时，应明确目标时区和转换策略，按具体需求选择实现。

## 四、Harness 执行与审查

1. 编码前同时读取 [Go 编码规范入口](go-style.md)和本文件，按规则编号确定本次涉及的项目约定。
2. 审查新增和修改代码的实际调用，确认 JSON、errors 和时间操作采用正确入口；导入别名不能作为判断依据。
3. 涉及高性能路径时检查可避免的 `defer`，并复核所有相关退出路径的清理行为；按变更运行适用的测试，并对性能结论进行测量。
4. 工具检查通过不能替代场景判断：高性能路径、强制时区要求和资源清理完整性需要结合代码语义审查。
5. 现有代码不构成豁免依据。新增和修改时在任务范围内落实规则，全仓库审计或批量迁移作为独立任务处理。

## 五、后续追加规则

- 在本文件追加新规则，使用递增、稳定的编号，从 `DUE-005` 开始；已有编号不重排、不复用。
- 每条规则写明适用场景、要求强度、指定包或实现方式，以及必要的实施边界。
- 同步更新规则索引；与 Uber 通用规范存在冲突时，明确覆盖范围，并更新 [Go 编码规范入口](go-style.md)中的对应说明。
- 废止规则时保留原编号并标注状态，方便历史变更和审查记录引用。
